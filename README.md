# Generator ERP Production

هذه نسخة إنتاجية أولية تحفظ البيانات في PostgreSQL، وليس في متصفح المستخدم.

للتطوير الصحيح لا تبدأ من الواجهات. اقرأ أولاً ملف البنية:

`ARCHITECTURE.md`

## المتطلبات

- PostgreSQL شغال على الجهاز أو السيرفر.
- Node.js.
- تثبيت حزم Node داخل هذا المجلد:

`npm install`

## إعداد PostgreSQL

أنشئ قاعدة بيانات باسم:

`generator_erp`

يمكن استخدام ملف:

`postgresql-setup.sql`

ثم عرّف الاتصال قبل التشغيل:

`set DATABASE_URL=postgres://postgres:YOUR_PASSWORD@127.0.0.1:5432/generator_erp`

ثم شغل:

`start-postgres-production.cmd`

إذا كان PostgreSQL غير مثبت أو غير شغال، سيظهر خطأ اتصال مثل `ECONNREFUSED 127.0.0.1:5432`.

## التشغيل

افتح الملف:

`start-postgres-production.cmd`

ثم افتح:

`http://127.0.0.1:8090`

لفحص صحة السيرفر بعد التشغيل:

`check-production.cmd`

أو افتح:

`http://127.0.0.1:8090/api/health`

## التشغيل التلقائي بمفتاح فلاش

ويندوز يمنع Autorun المباشر من الفلاش غالبا لأسباب أمنية، لذلك يوجد حل آمن:

1. افتح `create-usb-key.cmd` وأنشئ ملف المفتاح داخل الفلاش.
2. افتح `install-usb-key-autostart.cmd` مرة واحدة فقط.
3. بعد ذلك عند تشغيل الجهاز ووجود الفلاش، أو عند إدخال الفلاش، يعمل النظام تلقائيا في الخلفية.
4. افتح النظام من:

`http://127.0.0.1:8090`

لإلغاء هذه الميزة افتح:

`uninstall-usb-key-autostart.cmd`

## الدخول الأول

- المستخدم: `admin`
- كلمة المرور: `ChangeMe-12345`

يجب تغيير كلمة المرور قبل إدخال بيانات الشركة الحقيقية.

## مكان البيانات

- قاعدة البيانات: PostgreSQL.
- الجداول الأساسية: `users`, `accounts`, `customers`, `suppliers`, `items`, `audit_log`, `app_records`.
- النسخ الاحتياطية الخارجية يجب إعدادها من PostgreSQL مثل `pg_dump`.
- سجل التشغيل: `logs/app.log`

## النسخ الاحتياطي

بعد تعريف `DATABASE_URL` وتشغيل أدوات PostgreSQL:

`backup-postgres.cmd`

ينشئ نسخة بصيغة PostgreSQL custom dump داخل مجلد `backups`.

لإنشاء نسخة يدوية الآن افتح:

`backup-postgres.cmd`

لإنشاء مهمة نسخ احتياطي يومية الساعة 23:00 افتح هذا الملف كمسؤول:

`create-daily-backup-task.cmd`

ينصح بنسخ ملفات `backups/*.dump` يوميا إلى قرص خارجي أو Google Drive/OneDrive منفصل عن جهاز التشغيل.

## ثبات البنية

- إعدادات التشغيل من `.env` أو متغيرات البيئة.
- السيرفر يملك فحص صحة `/api/health`.
- كل طلب API يسجل في `logs/app.log`.
- كل تعديل مالي أو إداري يسجل في جدول `audit_log`.
- الجداول تنشأ تلقائياً عند التشغيل الأول.
- يوجد جدول `schema_migrations` لتثبيت نسخ قاعدة البيانات.
- يوجد إغلاق آمن للسيرفر عند الإيقاف.

## قوالب الفواتير وExcel

- يمكن رفع تصميم فاتورة Word بصيغة `.docx` من شاشة "استيراد تصميم فاتورة Word".
- تحفظ القوالب داخل PostgreSQL في جدول `invoice_templates`.
- يمكن تصدير التقارير إلى Excel من أزرار التصدير في شاشة البيانات.
- تصدير Excel يستخدم ملفات `.xlsx` منظمة بعدة sheets عند اختيار "كل التقارير".

## ملاحظات مهمة

- لا توجد بيانات وهمية في قاعدة الإنتاج.
- البيانات الحقيقية يجب إدخالها من سجلات شركتك أو استيرادها من ملفاتك.
- كل تعديل عبر API يدخل في سجل التدقيق داخل PostgreSQL.
- هذه نواة إنتاجية أولى. قبل الاعتماد النهائي كمصدر وحيد يجب إكمال كل عمليات المبيعات والمشتريات والقيود على السيرفر، ثم عمل نسخة احتياطية خارجية يومية.

## إضافات سندات القبض والافتتاحيات

- سند القبض يدعم نوع السند: عربون، تكملة حساب، تسديد حساب قديم.
- طريقة القبض تدعم نقدا أو دفع إلكتروني. عند اختيار دفع إلكتروني يتم ترحيل المدين مباشرة إلى حساب `1621` مصرف المنصور الاستثماري دينار.
- القيد الافتتاحي يحفظ كسطور مدينة ودائنة، ولا يتم حفظه في الواجهة أو السيرفر إذا لم يكن مجموع المدين مساويا لمجموع الدائن.
- قيد بضاعة أول مدة يضيف أو يحدث كمية الصنف في المخزن، ويرحل محاسبيا إلى حساب المخزون المناسب `1211`/`1212`/`1213` مقابل `31` رأس المال أو الحساب الذي تختاره.
- تقارير Excel تشمل سندات القبض، القيود الافتتاحية، وبضاعة أول مدة.

## أساس محاسبي مهم

- دليل الحسابات يعتمد الهيكل الرسمي العملي للنظام المحاسبي الموحد العراقي: الموجودات، المطلوبات، حقوق الملكية، الإيرادات، المصروفات، والحسابات النظامية.
- الرصيد لا يعتمد على حقل محفوظ داخل الحساب. الرصيد يظهر محسوبا من القيود اليومية في دفتر الأستاذ.
- حقل `accounts.balance` متروك فقط للتوافق مع النسخ السابقة ولا يستخدم كمصدر للحقيقة.
- أي حركة مالية يجب أن تمر بقيد محاسبي متوازن، ثم تظهر في دفتر الأستاذ وكشف الحساب.
- الفاتورة ليست مركز النظام؛ هي مستند ضمن دورة تبدأ بالقيد المحاسبي وحركة المخزون ودورة الموافقات.
- القيود الجديدة تحفظ في `journal_entries` و`journal_lines`، وليس فقط داخل سجل عام.
- المخزون له حركات `stock_moves` وطبقات كلفة `inventory_layers` حتى يدعم FIFO/الكلفة المتوسطة لاحقا وتتبع السيريال والضمان.
- لا توجد حذف للحركات المالية؛ التصحيح الصحيح يكون بقيد عكسي أو سير إلغاء واعتماد.
- توجد بنية لفترات الإقفال `fiscal_periods`: أي فترة مغلقة تمنع ترحيل قيود جديدة داخلها.
